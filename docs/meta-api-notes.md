# Meta Model API notes (from dev.meta.ai docs, read and cross-checked 2026-10-28)

##### SAM 3.1 (sam-3.1) on Meta Model API: video and image segmentation request and re
- SAM 3.1 uses model id sam-3.1 for both images and video, over POST /v1/responses on https://api.meta.ai/v1 with a Bearer key. Requests use the OpenAI-compatible Responses API, so the OpenAI SDK works with base_url https://api.meta.ai/v1.
- A request is one user message with an input_text part (the prompt) and one media part: input_image with image_url, or input_video with video_url or file_id. image_url and video_url can each be a public URL or a base64 data URL.
- Accepted video formats are MP4 or MOV with H.264, H.265 or MPEG-4. VP9 and WebM are rejected.
- A request can cover up to 15,000 frames (about 10 minutes). Video tracks up to 16 objects per frame. Image requests return every matching instance. Box and point prompts can name up to 16 objects.
- Size limits: inline content (base64 or URL in the request body) is capped at 50 MB, and Files API uploads at 1 GiB. Each team has 100 GiB of storage in total. Uploaded files never expire unless expires_after is set.
- To upload a video, POST /v1/files as multipart with purpose=user_data. The upload is synchronous: a 200 means the file is ready to use. The response returns an id such as file-842549258569145, and you pass it as input_video.file_id. Docs curl: curl -X POST "https://api.meta.ai/v1/files" -H "Authorization: Bearer $MODEL_API_KEY" -F "purpose=user_data" -F "file=@/path/to/clip.mp4"
- Example upload response: {"id":"file-842549258569145","object":"file","bytes":245832,"created_at":1714502400,"filename":"clip.mp4","purpose":"user_data","status":"uploaded"}
- Uploaded MP4s whose moov atom is not at the front are remuxed losslessly for faststart. Frames and timestamps do not change. The docs recommend exporting with ffmpeg -i input.mp4 -c copy -movflags +faststart output.mp4.
- Docs curl for video by URL: curl -N -X POST "https://api.meta.ai/v1/responses" -H "Authorization: Bearer $MODEL_API_KEY" -H "Content-Type: application/json" -H "Accept: text/event-stream" -d '{"model": "sam-3.1", "input": [{"type": "message", "role": "user", "content": [{"type": "input_text", "text": "red bicycle"}, {"type": "input_video", "video_url": "https://example.com/clip.mp4"}]}], "stream": true}'
- Docs curl for video by file id: the same request as the URL example, but the content is [{"type": "input_text", "text": "delivery van"}, {"type": "input_video", "file_id": "file-abc123"}] with "stream": true.
- Docs curl for an image: curl -N -X POST "https://api.meta.ai/v1/responses" -H "Authorization: Bearer $MODEL_API_KEY" -H "Content-Type: application/json" -H "Accept: text/event-stream" -d '{"model": "sam-3.1", "input": [{"type": "message", "role": "user", "content": [{"type": "input_text", "text": "glasses"}, {"type": "input_image", "image_url": "https://example.com/photo.png"}]}], "stream": true}'
- A concept prompt is a short noun phrase naming one concept. Lists, negation, OR and spatial phrases are unreliable. To find several concepts, send one request per concept.
- Zero matches is a valid result: the stream completes with an empty output_text and no delta events.
- Box and point prompts go in input_text using the token grammar, with per-frame <Nf> markers and ids you choose, for example <0f>1<|box;x1=..;y1=..;x2=..;y2=..;w=..;h=..|>,2<|point;x=..;y=..;w=..;h=..|>-<|point;...|>. A '-' marks a negative point. w and h must be the media's displayed pixel size. One prompt cannot mix a phrase with boxes or points.
- The request parameters live in metadata, and their values are strings. metadata.mask_encoding is "lossless" (the default, marked ~) or "one_bit" (marked !, several times smaller). metadata.include_confidence is "true" or "false" (default: off). metadata.propagation_direction is both (the default), forward or backward, and applies to box and point prompts in video.
- Box and point prompts always return one_bit masks, whatever mask_encoding is set to.
- Streaming (stream:true) is recommended but optional. Each video frame arrives as its own response.output_text.delta, and the stream ends on response.completed. A non-streaming request returns the same format in one response. Results can vary slightly between runs.
- The response is special-token text in the output_text lane, not JSON: one line per frame. Each line is <Nf> followed by comma-separated records, and each record is an object id, a box token, then a mask token.
- Frame indices start at 0. A frame with no visible objects gets no line, so indices can skip. Concept prompts return frames in ascending order. With propagation_direction both, frames after the prompt come first, then earlier frames in descending order.
- The object id is a stable integer across frames within one response. Ids are sparse, not dense. Do not rely on an id across an object's entry, exit, full occlusion, or very long clips.
- Box x1, y1, x2 and y2 are in source pixels, and x2/y2 are inclusive. w and h are the source frame size. The mask's data value is H,W (height first), an encoding marker, then a base85 (not base64) payload. The optional c is a confidence from 0 to 1.
- The official parsers are npm @meta-sam/parser (0.0.13 or later needed for confidence) and pip meta-sam-parser (0.0.6 or later). decodeMaskToRaster returns a row-major 0/1 Uint8Array of length H*W. decodeMaskToRLE returns COCO RLE {size:[height,width], counts}. Python equivalents are decode_mask_to_raster and decode_mask_to_rle. @meta-sam/graphics, @meta-sam/video and @meta-sam/react also exist.
- Pricing: $2.50 per 1,000 images and $0.20 per 1,000 video frames. Each video request is billed for at least 50 frames, and usage.video_frames_processed reports the frames billed.
- The sam-3.1 rate limit is 3,000 requests per minute per team, with no token-per-minute limit.
- Invalid prompts or metadata return 400 with specific messages, for example 'invalid prompt: 17 objects exceed this model's limit of 16'. An unknown model, or a team without access, returns 404 with code model_not_found.
- Official cookbook: the code lives in the github.com/meta-models/meta-sam repo (an API Playground under typescript/examples/api-playground). A verified cookbook run of 'ping pong ball' on pingpong.mp4 returned one stable object across all 134 frames.
- The headlocked-captions cookbook's own preprocessing keeps the source frame rate and caps the longest video edge at 960 px. This is a cookbook client choice, not an API limit.

##### Meta Model API: Muse Spark (muse-spark-1.3/1.2/1.1 and -contributor variants). R
- The docs are machine-readable: llms.txt lists every page, and each page is served as Markdown at https://dev.meta.ai/docs/<page>.md
- Muse Spark has three versions (1.3, 1.2, 1.1). All accept text, image, video, audio and PDF input, return text, and have a 1,048,576-token context window. 1.3 is the recommended version.
- The -contributor variants are the same models in 'Contributor mode'. Prices are much lower in exchange for Meta's permission to train future models on your prompts, files and responses. Only 1.3 and 1.2 have a contributor variant; 1.1 is Standard mode only.
- In Standard mode your content is not used for training. You switch modes by choosing the model ID.
- Muse Spark prices per 1M tokens: Standard is $1.25 input, $0.15 cached input and $4.25 output. Contributor is $0.10 input, $0.002 cached input and $0.20 output. There is no long-context premium.
- Rate limits are per team. muse-spark-1.3, 1.2 and 1.1 allow 3,000 RPM and 4,000,000 TPM. The contributor variants allow only 150 RPM and 3,000,000 TPM.
- The API offers three request formats on the same models: Responses (POST /v1/responses, recommended), Chat Completions (POST /v1/chat/completions) and an Anthropic-compatible Messages endpoint (POST /v1/messages). Chat Completions does not carry reasoning across turns.
- The OpenAI SDK works with base_url https://api.meta.ai/v1 and a Bearer token, with the key kept in MODEL_API_KEY. The OpenAI SDK does not read MODEL_API_KEY automatically, so the key has to be passed in.
- Quickstart curl (Responses API), exactly as the docs show it: curl -X POST "https://api.meta.ai/v1/responses" -H "Authorization: Bearer $MODEL_API_KEY" -H "Content-Type: application/json" -d '{"model": "muse-spark-1.3", "input": "What is the capital of France?"}'
- Video works on both the Responses API and Chat Completions. The model reads the frames and the embedded audio together. The recommended flow is to upload the MP4 through the Files API (purpose user_data) and reference it by file_id.
- Step 1 of the video flow is the upload curl (multipart). The response returns an id such as file-842549258569145.
- Step 2 of the video flow is a Responses curl that references the uploaded video with an input_file block.
- A video can also be passed by URL with no upload, using an input_video block whose video_url is a public URL or a base64 data URL. input_video also accepts file_id.
- The Responses input_video schema has an optional fps field that sets the frame-sampling rate. If fps is omitted, the backend chooses the rate.
- On Chat Completions, the video content part has the shape {"type":"video_url","video_url":{"url":...,"fps":...}}. The url can be a link or base64 data.
- Only MP4 (video/mp4) is supported for video. Videos with no audio track are valid input.
- File size limits: 50 MB inline (file_data, file_url or a data URL) and 1 GiB through a Files API upload. Each team has 100 GiB of storage, and uploads never expire unless expires_after is set.
- Audio understanding on Muse Spark 1.3 is flagged as not fully supported, so the docs use 1.2 for audio examples. This matters for video soundtracks.
- Reasoning shares the output budget. The docs recommend at least 4000 max tokens for transcription, and streaming for long clips to avoid an idle timeout.
- Images can be sent as individual frames: input_image blocks on Responses (image_url is a plain string URL or data URL, or file_id) or image_url parts on Chat Completions. The limit is 50 images per request; more returns HTTP 400.
- Image token cost scales with resolution. A roughly 1280px image costs about 1,300–1,500 tokens. Exact counts come from POST /v1/responses/input_tokens.
- Responses image curl example, as shown in the docs.
- Structured output uses response_format (json_schema) on Chat Completions and text.format on Responses. Decoding is constrained, so the output always conforms to the schema. Recursive schemas return HTTP 400.
- Responses text.format takes the flat OpenAI shape {type:'json_schema', name, schema, strict?}, with name and schema required.
- Chat Completions structured-output curl, as shown in the docs.
- Schema limits: nesting depth 10, 5,000 properties in total, and 1,000 enum values by default. strict defaults to false. strict:true requires a plain-object root, additionalProperties:false and every key listed in required, and does not allow allOf or oneOf.
- Tool calling supports function and custom tools. On Responses the tool fields are flat; on Chat Completions they sit under a 'function' key. Only tool_choice 'auto' is supported (none, required and named choices return HTTP 400). parallel_tool_calls defaults to true.
- Tool arguments are guided by the parameters schema but are not guaranteed to validate against it. Function names may contain at most one dot, and call_id must be 1–64 characters.
- Chat Completions tool-calling curl, as shown in the docs.
- Reasoning effort is a top-level reasoning_effort on Chat Completions and reasoning.effort on Responses. Allowed levels are minimal, low, medium, high, xhigh and max. 'none' returns HTTP 400 on Muse Spark. 'max' works only on muse-spark-1.3, not on muse-spark-1.3-contributor. If the parameter is omitted, the model picks a level.
- Responses reasoning curl, as shown in the docs.
- Raw chain of thought is never returned. Responses can return a reasoning summary (reasoning.summary set to auto, concise or detailed) and encrypted reasoning for stateless replay (include: ['reasoning.encrypted_content']).
- max_output_tokens counts both reasoning and visible output (minimum 16). Input plus max output must fit within the context window, and only truncation 'disabled' is supported, so an overflow returns 400.
- Meta adds steering tokens (a system prompt and scaffolding) to every request. These tokens are not billed and are excluded from usage counts.

##### Meta Model API: Files/upload API (video upload, size limits, retention) and Muse
- The docs publish raw Markdown versions of every page at <page>.md, and they are listed in llms.txt, so no JS rendering is needed. Relevant pages: file-handling, api-reference/files/*, speech-to-text, api-reference/voice/*, video-understanding.
- Upload endpoint: POST https://api.meta.ai/v1/files, multipart/form-data, required fields `file` and `purpose` ('user_data' or 'batch'). Use user_data for images and videos that requests reference. Other OpenAI purposes return 400.
- Upload curl example, exactly as the docs show it.
- Size limits: inline is 50 MB and a Files API upload is 1 GiB. Larger files are rejected.
- Each team has 100 GiB of storage, shared across all its API keys. When it is full, uploads fail with HTTP 400. The schema says some teams can have a different allowance.
- Retention: uploaded files never expire by default. An optional expires_after setting (anchor=created_at, seconds from 3600 to 2592000, i.e. 1 hour to 30 days) makes them expire. Files can also be deleted with DELETE /v1/files/{file_id}.
- Upload-with-expiry curl example, exactly as the docs show it.
- For lower upload latency, send purpose and expires_after first and make file the last multipart part.
- The only supported video MIME type is video/mp4, and the model reads both the frames and the embedded audio. Supported audio types are audio/mpeg and audio/wav. File IDs look like file-<numeric>.
- An uploaded video is referenced by file_id in an input_file or input_video block on the Responses API, with model muse-spark-1.3. Docs curl example below.
- Audio understanding in Muse Spark 1.3 is not fully supported yet, so the docs' audio examples use Muse Spark 1.2. They also advise max_tokens of at least 4000 so a transcript does not come back empty.
- Muse Voice Transcribe has two endpoints. WebSocket wss://api.meta.ai/v1/asr/realtime authenticates in the handshake frame. POST https://api.meta.ai/v1/asr/transcribe takes a multipart file and uses the Authorization header.
- A transcribe request is multipart with a JSON `request` part and an `audio` part. The request fields are model (required), audioEncoding (required, only 'WAV'), mode (PUSH_TO_TALK by default, or ENDPOINTING or DIARIZATION), keywords, languageBias, partialMode and emitAudioProgress. The last two apply to SSE responses only.
- Transcribe curl example (reference page), exactly as the docs show it.
- Diarization curl example (feature page), exactly as the docs show it.
- SSE streaming curl example, exactly as the docs show it. Setting Accept to text/plain instead returns one turn per line, or lines like 'A:Hello' in diarization mode.
- Accepted audio for /asr/transcribe is WAV only: mono, 16-bit integer PCM at 16 or 24 kHz. Other formats must be converted first; the docs give an ffmpeg command. The realtime endpoint takes raw PCM_24KHZ or PCM_16KHZ (s16le mono).
- Transcribe limits: request body 32 MB (413 if over), audio 10 minutes (400 if over), and a 400 for any non-WAV file. 32 MB of 24 kHz s16 mono is about 11 min, so the 10-minute cap is the binding limit.
- Timestamps are per turn only. Each Turn has turnId, startMs, endMs, transcript, and speaker (diarization only). There are no word-level timestamps or confidence scores.
- startMs and endMs measure how much audio had been processed when the turn was detected. They are not precise acoustic boundaries. In PUSH_TO_TALK mode the turns array is empty, so use ENDPOINTING or DIARIZATION to get timestamps.
- The JSON response has the shape {sessionId, transcript, audioDurationMs, turns:[{turnId,startMs,endMs,transcript,speaker}]}.
- Supports 25 languages with code-switching. languageBias is a list of language names such as ["English","French"]. keywords biases toward specific vocabulary but does not guarantee spelling.
- Rate limits are 256 concurrent streams and 16,000 streams per hour per tenant, shared by both endpoints. A realtime session runs at most 60 minutes.
- Pricing is $0.18 per hour of processed audio, rounded down to whole seconds. Failed and 429 requests are not billed. ZDR costs the same as Standard mode, and Contributor mode is not available for this model.
- An official cookbook runs muse-voice-transcribe-1.0 together with sam-3.1 on an MP4 video and maps diarized speakers to tracked people. Its transcription step is a script that takes the mp4: scripts/transcribe.py input.mp4.

##### Meta Model API (dev.meta.ai): pricing, rate limits, errors, auth, SDKs, SAM 3.1 
- Base URL is https://api.meta.ai/v1. The Anthropic SDK and Messages API use https://api.meta.ai, and the SDK appends /v1/messages.
- Auth works with a Bearer token in the Authorization header. Keys start with LLM_ and are shown only once when created. The docs use the env var MODEL_API_KEY.
- Curl example from the auth docs (Chat Completions): curl https://api.meta.ai/v1/chat/completions -H "Authorization: Bearer $MODEL_API_KEY" -H "Content-Type: application/json" -d '{"model": "muse-spark-1.3", "messages": [{"role": "user", "content": "Hello"}]}'
- Quickstart curl example (Responses API).
- There is no Meta-specific SDK. You use the OpenAI SDK (Responses and Chat Completions), the Anthropic SDK (Messages), or any OpenAI-compatible client (LangChain, LlamaIndex, Vercel AI SDK, LiteLLM with an openai/ model prefix). None of them reads MODEL_API_KEY on its own, so pass the key explicitly.
- Python: pip install openai, then OpenAI(api_key=os.environ["MODEL_API_KEY"], base_url="https://api.meta.ai/v1"). TypeScript: npm install openai, then new OpenAI({ apiKey: process.env.MODEL_API_KEY, baseURL: "https://api.meta.ai/v1" }). With the Anthropic SDK, set base_url="https://api.meta.ai" and auth_token=MODEL_API_KEY. Its content starts with a redacted_thinking block, so read the text blocks.
- SAM 3.1 pricing: image segmentation is $2.50 per 1,000 images and video segmentation is $0.20 per 1,000 frames, the same for streaming and non-streaming. Each video request is billed for at least 50 frames. usage.video_frames_processed reports the frames billed. The docs do not give a per-second price.
- SAM 3.1 limits: MP4 or MOV with H.264, H.265 or MPEG-4 (no VP9 or WebM). Up to 15,000 frames (about 10 minutes) per request. Video tracks up to 16 objects per frame. Box and point prompts can name up to 16 objects. Tracking fewer frames (propagation_direction forward or backward) costs less.
- SAM 3.1 video curl example (streaming Responses API). Output is special-token text with one line per frame. Meta-SAM parser libraries are @meta-sam/parser (TS) and meta_sam_parser (Python).
- Files API upload curl example (max 1 GiB per upload, 50 MB inline, 100 GiB team storage, files do not expire by default).
- File size limits: 50 MB inline and 1 GiB through the Files API. Teams have 100 GiB of storage.
- Muse Spark token pricing per 1M tokens. Standard mode: cached input $0.15, input $1.25, output $4.25. Contributor mode (muse-spark-1.3-contributor or 1.2-contributor, where your content may be used for training): cached input $0.002, input $0.10, output $0.20. There is no long-context premium. Web search costs $2.50 per 1,000 queries.
- Muse Wonder (muse-wonder-1.0) pricing per 1M tokens: cached input $0.20, input $4.00, output $20.00. Standard mode only on the API.

- Error envelope is {error:{message,type,param,code}}. Types: invalid_request_error, authentication_error, rate_limit_error, server_error. Status codes: 400 (validation, content_policy_violation, undecodable media), 401 invalid_api_key, 402 billing_not_configured, 403, 404 model_not_found or file_not_found, 413 payload_too_large, 429 rate_limit_exceeded, 500, 503 server_shutting_down, service_overloaded or backend_unavailable (with Retry-After), 504 gateway_timeout. An unknown path returns 404 with an empty body. Do not retry 400, 401, 402, 403, 404 or 413.
- Pay-as-you-go billing: a team admin adds a payment method at dev.meta.ai/billing, then creates a key. The card is charged when the balance reaches a payment threshold, and on the 1st of each month.
- Muse Code is Meta's terminal and CI coding agent built for Muse Spark (default model muse-spark-1.2). The installer puts a native `muse` binary on your path. Install on macOS and Linux with: curl -fsSL https://dev.meta.ai/install.sh | sh. On Windows use: irm https://dev.meta.ai/install.ps1 | iex. Verify with: muse --version.
- Using Muse Code: run `muse` in a project for the interactive TUI. It asks you to trust the workspace and to sign in in the browser or with an API key; `/login` reopens these options. `muse exec "<prompt>"` runs headless. `muse serve` and `muse schema` expose the session protocol, and there is a TS SDK (npm install @muse-code/sdk). For CI, set META_API_KEY (not MODEL_API_KEY). An API key takes priority over a browser session.
- Muse Code subscription plans: Everyday Usage (10-50 prompts every 5 hours), High (5x), Power (20x, includes Muse Wonder Full) and Maximum (80x). They default to Contributor mode, work only through the Muse Code CLI, and usage through any additional API keys is billed pay-as-you-go.
